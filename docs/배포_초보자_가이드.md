## 5. 환경변수 전체 설정표

### 5-1. Vercel → Project → Settings → Environment Variables

운영 환경에는 아래 4개 변수가 필요합니다. Production, Preview, Development 중 실제 사용하는 환경을 선택하고 저장한 뒤 재배포합니다.

| 변수명 | 값 | 필수 여부 | 비밀 여부 |
|---|---|---|---|
| SUPABASE_URL | https://imadhwyhsgfjdqxbkoyr.supabase.co | 필수 | 공개 가능 |
| SUPABASE_PUBLISHABLE_KEY | Supabase Project Settings → API Keys의 Publishable key | 필수 | 공개 가능 |
| AURA_INFERENCE_URL | Colab에서 출력된 최신 HTTPS trycloudflare 주소 | 필수 | 공개 가능 |
| AURA_GATEWAY_SECRET | Colab Secrets와 동일한 긴 난수 문자열 | 필수 | 비밀 |

AURA_INFERENCE_URL은 Colab Quick Tunnel을 새로 시작할 때 바뀔 수 있습니다. 주소가 바뀌면 Vercel에서도 값을 갱신하고 재배포합니다.

### 5-2. AURA_GATEWAY_SECRET 만들기

Windows PowerShell에서 다음 명령을 실행합니다.

    [Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))

출력된 한 줄을 복사합니다. 이 문자열을 두 위치에 똑같이 입력합니다.
- Colab 왼쪽 열쇠 아이콘(Secrets) → 이름 AURA_GATEWAY_SECRET → 값 붙여넣기 → Notebook access 켜기
- Vercel → Settings → Environment Variables → 이름 AURA_GATEWAY_SECRET → 같은 값 붙여넣기

값을 채팅, GitHub, 코드 파일, 공개 화면에 붙여넣지 않습니다.

### 5-3. Supabase 환경변수

Supabase Dashboard → Project Settings → API Keys에서 확인합니다.
- Project URL → Vercel SUPABASE_URL
- Publishable key (sb_publishable_...) → Vercel SUPABASE_PUBLISHABLE_KEY
- service_role 또는 Secret key는 브라우저에 넣지 않습니다.

Google OAuth Client ID/Secret은 Vercel 변수가 아닙니다. Supabase → Authentication → Sign In / Providers → Google에 입력합니다.

### 5-4. Colab 런타임 내부 환경변수

노트북이 다음 값을 자동으로 설정합니다.

| 변수명 | 기본값 | 용도 |
|---|---|---|
| AURA_GATEWAY_SECRET | Colab Secrets에서 읽음 | Vercel 게이트웨이와 추론 서버 간 인증 |
| AURA_DEVICE | GPU 사용 가능 시 cuda, 아니면 cpu | 모델 실행 장치 |
| AURA_GPU_MEMORY_FRACTION | 0.33 | GPU 메모리 사용 비율 |
| AURA_CPU_THREADS | 2 | CPU 스레드 제한 |

Google Drive 인증이 실패하면 노트북은 /content/AuraAI-data 임시 저장소로 계속 실행합니다. 런타임이 종료되면 사라질 수 있으므로 영구 보존된다고 가정하지 않습니다.

### 5-5. 선택 변수

DATABASE_URL은 현재 웹 게이트웨이에서 사용하지 않습니다. 직접 PostgreSQL 연결 코드를 추가한 경우에만 서버 전용 변수로 설정합니다. 기존의 다른 프로젝트 DB 주소를 복사하지 마세요.

## 6. Supabase 데이터베이스
SQL 마이그레이션 파일:
supabase/migrations/202611050001_aura_core.sql

Supabase Dashboard → SQL Editor에서 해당 파일의 SQL을 실행합니다. 실행 후 Table Editor에서 aura_profiles, aura_conversations, aura_messages, aura_api_keys 테이블이 생성됐는지 확인합니다. 각 테이블은 RLS 정책으로 사용자별 데이터 접근을 제한합니다.

## 7. Colab 실행 및 재접속
1. colab/Aura_Inference_Colab.ipynb 파일을 Colab에 직접 업로드합니다.
2. 런타임 유형에서 GPU를 선택합니다(사용 가능한 경우).
3. Colab Secrets에 AURA_GATEWAY_SECRET을 등록하고 Notebook access를 허용합니다. Drive 인증에 실패해도 노트북은 임시 저장소로 계속 실행되며, 비밀값 자동 읽기가 실패하면 숨김 입력을 요청합니다.
4. 셀을 위에서부터 실행합니다.
5. 마지막 셀에 출력된 HTTPS 주소를 Vercel AURA_INFERENCE_URL에 등록합니다.
6. Vercel을 Redeploy합니다.

watchdog은 런타임이 살아 있는 동안 API와 Tunnel 프로세스가 종료되면 다시 실행합니다. Colab 런타임 자체가 종료되면 내부 코드도 멈추므로 새 세션에서 런타임 → 모두 실행을 해야 합니다. Quick Tunnel 주소는 세션마다 바뀔 수 있습니다.

## 11. 파일 첨부 및 모델 학습 한계

로그인한 사용자는 이미지, WAV 오디오, TXT/MD/CSV/JSON 및 PDF/DOCX/XLSX/PPTX 파일을 첨부할 수 있습니다. 문서 파일은 서버에서 텍스트를 추출해 질문에 포함합니다. 이미지·오디오는 현재 모델의 멀티모달 입력 경로로 전달됩니다. 첨부 총량은 Vercel 함수 요청 크기 제한을 고려해 약 3MB 수준으로 제한합니다.

현재 Aura는 사전학습 가중치를 가져온 상용 LLM이 아니라 자체 초기화된 약 4,790만 파라미터 모델입니다. 학습 버튼을 여러 번 누르는 것만으로 대규모 언어모델 수준의 이해 능력이 생기지는 않습니다. 데이터 품질, 데이터 양, 토크나이저, 모델 구조, 학습 시간과 검증이 모두 필요합니다. 문서의 텍스트 추출 기능과 모델 자체의 이해 능력은 서로 다른 문제입니다.
