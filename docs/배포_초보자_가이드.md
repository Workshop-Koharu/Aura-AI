# Aura AI 배포 가이드 (Vercel + Colab + Supabase)

## 0. 전체 구조

1. GitHub: 소스 코드 저장소
2. Vercel: 웹사이트와 로그인 확인을 담당하는 작은 Node.js API 게이트웨이
3. Supabase: 회원가입, 로그인, 사용자별 대화 데이터베이스
4. Google Colab: 모델 학습 및 추론을 위한 임시 GPU 런타임
5. Cloudflare Tunnel: Colab의 로컬 API를 HTTPS로 연결

Vercel에는 PyTorch를 설치하지 않습니다. 모델 파일과 torch는 Colab 런타임에서만 실행합니다.

## 1. Vercel 설정

1. Vercel Dashboard에서 aura-ai 프로젝트를 엽니다.
2. Settings → Build and Deployment로 이동합니다.
3. Root Directory를 web로 설정합니다.
4. Framework Preset은 Other로 설정합니다.
5. Build Command, Output Directory, Install Command는 비워 둡니다.
6. 저장합니다.
7. Deployments에서 main 브랜치의 새 배포가 시작되는지 확인합니다.

이 설정이 핵심입니다. 저장소 최상위에는 Python 프로젝트와 torch 의존성이 있지만, web 폴더에는 정적 웹 UI와 가벼운 Node API만 있습니다. Root Directory를 web로 바꾸면 Vercel 빌드가 최상위 pyproject.toml을 AI 추론 앱으로 취급하지 않습니다.

## 2. Vercel 환경변수

Project → Settings → Environment Variables에서 아래 항목을 추가합니다.

- SUPABASE_URL: Supabase 프로젝트의 HTTPS API 주소
- SUPABASE_PUBLISHABLE_KEY: Supabase의 공개 publishable key
- AURA_INFERENCE_URL: Colab 터널에서 발급된 HTTPS URL (마지막 / 없이)
- AURA_GATEWAY_SECRET: 본인이 만든 긴 무작위 비밀 문자열

Production 환경에 우선 등록합니다. Preview도 테스트하려면 Preview 환경에도 같은 변수를 등록합니다. 환경변수를 추가하거나 변경한 뒤에는 반드시 Redeploy해야 합니다.

AURA_GATEWAY_SECRET은 Colab의 Secrets에도 같은 값으로 넣습니다. 이 값은 브라우저, GitHub, 공개 문서에 넣지 않습니다.

## 3. Colab 노트북 열기

GitHub에 업로드된 뒤 다음 주소로 노트북을 엽니다.

https://colab.research.google.com/github/Workshop-Koharu/Aura-AI/blob/main/colab/Aura_Inference_Colab.ipynb

1. Google 계정으로 Colab에 로그인합니다.
2. 노트북 상단의 연결 버튼을 누릅니다.
3. Runtime → Change runtime type을 엽니다.
4. Hardware accelerator에서 GPU를 선택할 수 있으면 선택합니다.
5. 저장합니다.
6. 위에서부터 셀을 순서대로 실행합니다.

GPU가 제공되지 않으면 CPU로 실행되므로 응답 속도가 느릴 수 있습니다.

## 4. Colab Secrets 설정

1. Colab 왼쪽 세로 메뉴에서 열쇠 모양 Secrets를 선택합니다.
2. Add a new secret을 누릅니다.
3. 이름은 AURA_GATEWAY_SECRET으로 입력합니다.
4. 값은 본인이 생성한 긴 무작위 문자열을 붙여 넣습니다.
5. Notebook access를 켭니다.
6. 저장합니다.

같은 문자열을 Vercel의 AURA_GATEWAY_SECRET 환경변수에 등록합니다. 두 값이 정확히 일치해야 합니다.

## 5. Drive 영구 저장

노트북의 Drive 연결 셀을 실행하고 Google Drive 접근을 승인합니다. 다음 폴더가 만들어집니다.

My Drive/AuraAI/data

이 폴더에 다음 항목이 보관됩니다.

- text: 텍스트 학습 자료
- image_text: 이미지와 설명 쌍
- audio_text: 음성과 전사문 쌍
- checkpoints: 모델과 optimizer 체크포인트
- tokenizer: 토크나이저 파일

Colab 런타임이 종료되어도 Drive의 파일은 유지됩니다.

## 6. 학습 데이터 넣기

1. 사용 권한을 보유한 텍스트 자료를 UTF-8 TXT로 준비합니다.
2. 노트북의 파일 업로드 셀을 실행합니다.
3. TXT 파일을 선택합니다.
4. Drive의 AuraAI/data/text 폴더에 저장됐는지 확인합니다.
5. 학습 시작 셀을 실행합니다.
6. RUNNER.status()로 step, loss, 상태를 확인합니다.

이미지와 음성 데이터는 별도의 학습용 페어 파일 구조가 필요합니다. 단순히 파일만 올린다고 이미지/음성 이해 능력이 자동으로 생기는 것은 아닙니다. 모델 구조, 데이터 품질, 학습량, 평가가 모두 필요합니다.

현재 모델은 47,895,456 파라미터의 실험용 무작위 초기화 모델입니다. 학습이 끝나지 않았거나 데이터가 부족하면 일반적인 대화형 AI처럼 답하지 못합니다.

## 7. 추론 서버 실행과 URL 연결

노트북 마지막 실행 셀은 다음을 수행합니다.

1. FastAPI 추론 서버를 127.0.0.1:8000에서 실행합니다.
2. Cloudflare Quick Tunnel을 실행합니다.
3. https://....trycloudflare.com 형태의 임시 URL을 출력합니다.

출력된 URL 전체를 복사해 Vercel의 AURA_INFERENCE_URL에 넣습니다. 끝에 슬래시를 붙이지 않습니다. Vercel을 Redeploy합니다.

Quick Tunnel 주소는 Colab 런타임이 재시작되면 바뀔 수 있습니다. 주소가 바뀌면 Vercel 환경변수도 수정하고 다시 배포해야 합니다. 고정 주소를 쓰려면 소유한 도메인과 Cloudflare Named Tunnel 설정이 별도로 필요합니다.

## 8. 동작 확인

Vercel 배포 주소에서 아래 순서로 확인합니다.

1. 웹사이트 접속
2. 이메일 회원가입 또는 Google 로그인
3. 이메일 인증이 필요한 경우 메일 인증
4. 대화 화면 진입
5. 테스트 메시지 전송
6. 모델 상태와 Colab 로그 확인

로그인 전에는 대화 API가 401을 반환하고, Colab 주소가 등록되지 않았으면 503을 반환하는 것이 정상입니다.

## 9. Colab 24/7 관련 제한

Colab은 일반적인 24/7 서버 호스팅 상품이 아닙니다.

- 무료 런타임은 일반적으로 최대 12시간 수준이며, 실제 제한은 가용성과 사용 패턴에 따라 달라집니다.
- Pro+는 충분한 컴퓨팅 단위가 있을 때 최대 24시간 연속 실행을 지원할 수 있지만 영구 가동을 보장하지 않습니다.
- 런타임이 종료되면 추론 API와 임시 터널도 중단됩니다.
- 사용 제한을 우회하거나 사용자 활동을 흉내 내는 방식은 사용하지 않습니다.
- 글로벌 공개 서비스의 상시 추론에는 전용 GPU VM 또는 상시 가동이 보장되는 GPU 호스팅이 필요합니다.

이 노트북은 Drive 체크포인트를 보존하고 세션 종료 후 수동으로 다시 연결하는 개발용 구성입니다.

## 10. 데이터베이스 연결

제공된 프로젝트 참조는 oepokvfjlbrfnqcpcpri로 확인되지만, 현재 연결된 Supabase 관리 계정의 프로젝트 목록에는 나타나지 않았습니다. 따라서 이 환경에서는 해당 프로젝트의 테이블을 직접 생성하거나 연결을 검증하지 못했습니다.

데이터베이스 비밀번호가 대화에 노출되었으므로 Supabase Dashboard → Project Settings → Database에서 먼저 비밀번호를 재설정하세요. 새 비밀번호는 채팅이나 GitHub에 붙여 넣지 말고 서버 전용 환경변수에만 저장해야 합니다.

스키마 초안은 supabase/migrations/202611050001_aura_core.sql에 있습니다. 올바른 Aura Supabase 프로젝트를 선택한 후 SQL Editor에서 검토하고 실행합니다. 사용자별 데이터는 RLS 정책으로 분리합니다.
